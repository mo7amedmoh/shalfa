# منصة إدارة مشروع إدارة المرافق المدرسية

واجهة عربية RTL لإدارة بيانات المدارس وخطط المرافق والقوى العاملة ومؤشرات الأداء.

## المتطلبات المحلية

- Node.js LTS وnpm.
- مشروع Supabase مجاني (Postgres وAuth وRLS وStorage). لا يحتاج هذا المشروع إلى خادم مخصص أو مفتاح خدمة داخل المتصفح.

## التشغيل

1. انسخ `.env.example` إلى `.env.local` وأضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` من إعدادات مشروع Supabase. إذا غاب أحدهما تعرض شاشة الإعداد اسمه فقط دون كشف أي قيمة. يمكن استخدام مفتاح anon القديم كبديل للمفتاح العام. لا تضع `service_role` أو أي مفتاح سري في ملف عميل أو إعدادات بناء الواجهة.
2. نفّذ `npm install`.
3. تأكد من تطبيق المخطط المرجعي `docs/reference/001_shalfa_schema_rls.sql` مرة واحدة، ثم طبّق ترحيلات الميزات التي تستخدمها من `supabase/migrations/`.
4. أنشئ المستخدم الأول من Supabase Auth ببريده الكامل؛ ينشئ trigger الملف في `profiles`. بعد التحقق من هويته، غيّر دوره من SQL Editor مثلاً عبر `update public.profiles set role = 'admin' where username = 'your_username';`.
5. قبل نشر وظيفة إنشاء الحسابات الآمنة، طبّق `supabase/migrations/202611250002_fix_profile_role_insert_trigger.sql` إذا لم يكن مطبقاً، لضمان أن trigger إنشاء الملف الشخصي يعيّن `role_id` عند الإدراج. ثم ثبّت Supabase CLI ونفّذ `supabase functions deploy create-user`. تحقّق من توفر `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` كأسرار بيئة الوظيفة؛ لا تضع مفتاح الخدمة في `.env.local` أو إعدادات واجهة الويب. الوظيفة تتحقق من صلاحية الإنشاء، ويُسجل إنشاء الملف بواسطة trigger قاعدة البيانات.
6. شغّل `npm run dev`.

الأوامر المتاحة: `npm run lint`، `npm run typecheck`، `npm test`، `npm run build`.

## تقرير تحضير عمالة النظافة

يتيح «منجز التقارير» رفع قالب PowerPoint والبحث تلقائياً عن المدرسة بالاسم أو الرقم الوزاري في جدول `schools` (المزامَن من ورقة Google)، ثم إضافة صورة مستقلة لكل نسخة من الشريحة الثانية مع الحفاظ على أبعادها دون قص. يحافظ ملف PowerPoint الناتج على القالب، ويحوّل تصدير PDF العرض الناتج محلياً في المتصفح مع صفحة لكل شريحة.

يتحقق `npm run build` تلقائياً من أن JavaScript الابتدائي لا يتجاوز 400 KiB gzip. لتوليد تقرير تحليل الحزمة بصرياً استخدم PowerShell: `$env:ANALYZE='true'; npm run build`، ثم افتح `dist/stats.html`. راجع [تقرير الأداء](docs/PERFORMANCE.md) للقياسات والحدود المعروفة.

## مزامنة المدارس

بعد تسجيل مدير النظام، افتح «المزامنة والإعدادات» وأدخل اسم التبويب وعناوين الرقم الوزاري واسم المدرسة. يمكن ضبط مزامنة تلقائية عند دخول المدير وفق الفترة المحددة، كما تتوفر المزامنة اليدوية. يجب تأكيد أي أعمدة إحداثيات قبل إدخالها. المزامنة لا تحذف السجلات الغائبة من المصدر. يلزم تحديد التبويب/الإحداثيات والتحقق من سياسة RLS في مشروعك قبل استخدامها تشغيلياً.

## توزيع الخطط وتحديثها

تتيح الخطط الشهرية والمخصصة معاينة توزيع المدارس والمشرفين قبل الحفظ، مع حدود يومية قابلة للضبط واستثناء أيام العطلة. ويمكن تحديث صفوف الخطة الموجودة بلصق أرقام وزارية مفصولة بمسافات أو فواصل؛ تعرض المعاينة الأرقام المطابقة وخارج الخطة وغير الموجودة، ولا تنشئ صفوفاً جديدة. يلزم تطبيق `supabase/migrations/202611070002_bulk_plan_updates.sql` لتفعيل التحديث الجماعي وسجل التدقيق.

تتيح صفحة «إعادة توزيع المتبقي» تسجيل الإجازات الرسمية وإعادة جدولة الزيارات غير المنجزة. يلزم تطبيق `supabase/migrations/202611170003_redistribute_monthly_plan_rows.sql` على قاعدة بيانات Supabase؛ فهو ينشئ جدول `plan_holidays` ودالة الحفظ.

تدعم الخطط العامة تحديث الصفوف المحددة من الجدول، أو مطابقتها بأرقام/أسماء المدارس، أو استيراد تحديثات من قالب Excel، مع معاينة قبل التطبيق. يلزم تطبيق `supabase/migrations/202611150002_general_plan_bulk_updates.sql` لتفعيل التحديث الجماعي وسجل تدقيقه.

تتيح صفحة «إدارة الخطط» تصدير جميع الخطط الشهرية والعامة والمخصصة إلى ملف Excel، بما يشمل أنواع الخطط المخصصة المخفية والفترات وصفوف المدارس.

## التسكين والإعدادات

يمكن لكل مستخدم حفظ طريقة العرض المختصرة أو التفصيلية لتسكين العمالة. تُدار مزامنة المدارس، وأهلية الخطط، وربط الأسماء، وفحوص المخطط من مركز «الإعدادات». تُحفظ بيانات البوابين عبر `save_gatekeeper` لربط كل سجل بموظف من فئة حراس المدارس؛ ويتيح مدير النظام أو مدير المشروع تشغيل `backfill_gatekeeper_employees` لتسوية السجلات السابقة مع تسجيل العملية في سجل التدقيق.

لتفعيل تغييرات هذه المجموعة، طبّق بالترتيب `202611070001_ministry_key.sql` و`202611070002_bulk_plan_updates.sql` و`202611090001_school_cleanup.sql` و`202611100001_gatekeeper_category.sql` و`202611100002_gatekeeper_employee_links.sql` من مجلد `supabase/migrations/`.

## استيراد ملفات مؤشرات الأداء

ضع الملفين الرسميين في `docs/reference/` وشغّل `npm run seed:kpi` لإنتاج بيانات seed خاصة بالمستودع. بعد تطبيق المخطط، شغّل `npm run seed:kpi:database` و`npm run seed:checklist` من بيئة موثوقة تتوفر فيها `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`؛ لا تُعرّض مفتاح الخدمة للعميل. تُحمّل واجهة مؤشرات الأداء وقائمة الفحص من قاعدة البيانات مع سياسات RLS، ولا تُخدّم كتالوجاتها من `public/`.

للتحقق من السياسات، عيّن `TEST_<ROLE>_EMAIL` و`TEST_<ROLE>_PASSWORD` لكل دور وشغّل `npm run verify:rls`. بيانات الاعتماد لا تُحفظ في المستودع.

## النشر على Vercel

1. استورد مستودع GitHub إلى Vercel واختر إطار Vite؛ إعدادات البناء ومجلد `dist` وإعادة توجيه مسارات SPA ورؤوس الأمان مضبوطة في `vercel.json`.
2. أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` ضمن متغيرات البيئة في إعدادات المشروع، على الأقل لبيئة Production. أعد النشر بعد تغيير المتغيرات؛ فهي تُضمّن أثناء البناء.
3. أضف نطاق Vercel إلى إعدادات Redirect URLs في Supabase Auth، واضبط Site URL على النطاق الأساسي للإنتاج.

لا تضف `SUPABASE_SERVICE_ROLE_KEY` أو أي بيانات اعتماد خادمية إلى متغيرات Vercel الخاصة ببناء الواجهة. لا تضع بيانات المدارس أو الموظفين في ملفات ساكنة أو متغيرات عامة.

## النشر على مضيفات ثابتة أخرى

يمكن النشر عبر Cloudflare Pages أو Netlify أو GitHub Pages:

- أمر البناء: `npm run build`
- مجلد النشر: `dist`
- أضف متغيري Vite السابقين كمتغيرات بيئة وقت البناء.
- على Cloudflare Pages أو Netlify، تأكد من إعداد fallback إلى `index.html` لمسارات SPA. يوفّر `public/_headers` رؤوس الأمان للمضيفات التي تدعم صيغة `_headers`.
- أضف نطاق النشر إلى إعدادات Redirect URLs في Supabase Auth.

لا تضع بيانات المدارس أو الموظفين في ملفات ساكنة أو متغيرات عامة.
