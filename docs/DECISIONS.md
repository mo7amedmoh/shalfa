# القرارات التقنية

## الحزم

| الحزمة | سبب الاستخدام |
|---|---|
| Vite، React، React DOM، TypeScript | منصة البناء وواجهة تفاعلية ذات أنواع صارمة |
| Tailwind CSS، PostCSS، Autoprefixer | رموز التصميم وتنسيق RTL المتجاوب |
| `@fontsource/cairo` | تضمين الخط محلياً دون CDN خارجي |
| React Router | التنقل بين وحدات النظام |
| TanStack Query | جلب البيانات وتخزينها المؤقت من Supabase |
| `@tanstack/react-query-persist-client` | حفظ استعلام المدارس فقط للعمل دون اتصال؛ تُقيد سياسة التخزين على `['schools']` ولا تحفظ بيانات الموظفين أو البوابين أو أرقام الإقامة |
| React Hook Form | إدارة حقول نموذج الدخول والتحقق قبل الإرسال |
| Supabase JS | Auth وPostgres وRLS وStorage على الخطة المجانية |
| Zod | التحقق من بيانات الإعدادات والمدخلات |
| PapaParse | قراءة CSV من Google Visualization |
| Leaflet وReact Leaflet | خريطة المدارس مع OpenStreetMap |
| React Leaflet Cluster | تجميع علامات المدارس عند تقاربها بالخريطة |
| Recharts | رسوم مؤشرات الأداء وتقارير الخطط |
| SheetJS (`xlsx`) | قراءة ملفات KPI الرسمية، واستيراد Excel داخل المتصفح، وتبادل Excel؛ يؤخذ الإصدار 0.20.3 من CDN الرسمي لأن سجل npm لا يحدّث الحزمة بعد 0.18.5 المتأثرة بتحذيرات أمنية |
| npm override لـ `minimatch` | تثبيت الإصدار المصحح 11.0.1 لإزالة تحذير DoS متوسط في سلسلة ESLint/TypeScript ESLint؛ تم التحقق من نجاح lint وbuild بعد التغيير |
| Lucide React | أيقونات واجهة متسقة |
| Vitest | اختبارات وحدات منطق النطاق |
| ESLint وTypeScript ESLint | فحص جودة الشيفرة والأنواع |
| `tsx` | تشغيل سكربت seed المكتوب بـ TypeScript |

تُزال أي حزمة يتضح أنها غير مستخدمة أثناء اكتمال الوحدات. لم تُضف مكتبة PDF؛ التصدير الطباعي يعتمد CSS و`window.print()` حفاظاً على تشكيل العربية.

## قرارات المعمارية

- تسجيل الدخول بالبريد الإلكتروني الكامل عبر Supabase Auth. اسم المستخدم المعروض في «حسابي» للقراءة فقط وتديره قاعدة البيانات.
- إنشاء حساب Auth من واجهة الإدارة يتطلب واجهة Admin API ذات مفتاح خدمة؛ لذلك يُنفّذ عبر Supabase Edge Function تتحقق من JWT ودور المدير، ويُنشأ صف `profiles` بواسطة trigger قاعدة البيانات. لا يتضمن التطبيق الثابت أي مفتاح خدمة.
- المدارس تحفظ كمرآة مصدر JSONB لتغطية الأعمدة القادمة دون فقدها؛ لا تُنسخ بيانات المصدر إلى ملفات ثابتة.
- تكرار الرقم الوزاري لا يمنع المزامنة ولا يسقط أي صف. `schools.ministry_no` غير فريد، و`source_key` فريد حسب رقم الظهور في الورقة؛ تحفظ `source_columns` الرؤوس والقيم بترتيب المصدر، وتُعلّم الصفوف الغائبة دون حذفها. تعرض واجهتا المدارس والمزامنة التحذيرات وتقرير الإدراج والتحديث والتكرار والغياب والإحداثيات غير الصالحة.
- أهلية كل الخطط الشهرية والعامة تستبعد `مشترك ملحق`. خطة المصاعد تشترط كذلك وجود مقاول مصاعد. يبقى حجم المصدر `S/M/L` مطبعاً إلى `small/medium/large`، بينما يعتمد التسكين على عدد الفصول.
- شاشة المدارس والخريطة للقراءة فقط من آخر نسخة مخزنة عند انقطاع الشبكة؛ قد لا تتوفر بلاطات الخريطة دون اتصال. لا تُخزن أي بيانات شخصية أو أرقام إقامة في ذاكرة التخزين الدائمة.
- قائمة الفحص CM/OM ليست صفحة أو عنصر قائمة؛ جدول `checklist_items` وبياناته محفوظان كما هما، ويعدان خاملين حتى قرار لاحق.
- لوحة التحكم تعرض ملخص الخطة الشهرية والخدمات والإجراءات المباشرة من إسقاطات أعمدة محددة؛ لا تستعلم عن صفوف المدارس كاملة. تُحمّل بيانات المخرجات وبطاقة KPI فقط للأدوار المسموح لها بقراءتها وفق RLS.
- فلاتر لوحة التحكم للشهر والخدمة والمشرف محفوظة في عنوان الصفحة، وتطبق على المؤشرات المرتبطة بالخطط؛ بطاقة KPI والنشاط يتبعان الشهر المحدد، بينما المخرجات التعاقدية إجمالية والتغطية تعرض اللقطة التشغيلية الحالية لأنها ليست موزعة حسب الخدمة أو المشرف. تُوضح البطاقات نطاق البيانات غير المرتبط ببعد الفلتر لتجنب الإيحاء بأنها مصفاة.
- واجهة لوحة التحكم تتبع مجال الدور: مدير النظام ومدير المشروع يريان كامل الملخص؛ مهندس المنطقة يرى الخطط والتسكين والمكافآت دون KPI أو التدقيق؛ متابع التقارير يرى اختصار التحديث الجماعي والزيارات المتأخرة؛ المشرف والمشاهد يريان حكم الخطة وبطاقات الخدمات للقراءة فقط. تظل سياسات RLS هي مرجع البيانات المسموح بها ولا تستبدلها هذه الواجهة.
- تصنيف لوحة التحكم: على المسار عند عجز زيارات لا يتجاوز 5% من إجمالي الخطة، ومتأخر قليلاً عندما يتجاوز 5% وحتى 15%، ومتأخر كثيراً عند عجز أكبر من 15%. حدود التصنيف تطبق على الزيارات المنجزة مقارنة بالزيارات المتوقعة حتى التاريخ؛ بطاقات الخدمات تقارن متوسط إنجاز الزيارات والتقارير بالمتوقع، مع الحدود نفسها. الخدمة بلا صفوف خطة تعرض «لا توجد خطة» بدلاً من نسبة مصطنعة.
- لكل خطة شهرية اختيار مستقل: احتساب الزيارات المتأخرة حسب الموعد المخطط، أو متابعة التقدم حسب وتيرة الإنجاز. في وضع الوتيرة، الزيارات المتوقعة حتى اليوم = سقف (إجمالي زيارات الخطة × أيام العمل المنقضية ÷ أيام العمل الكلية للشهر)، وأيام العمل من الأحد إلى الخميس؛ يظهر العجز الموجب بين المتوقع والمنجز كمؤشر مستقل على فجوة الوتيرة، ولا يدخل في عدد الزيارات المتأخرة أو قوائمها. تُحتسب المتأخرات وقوائمها حسب الموعد المخطط فقط، ويُطبق ذلك في التقرير ولوحة التحكم والخطة. تغيير الخيار يتطلب صلاحية إدارة الخطط الشهرية.
- التزام مشرفي لوحة التحكم يخص الصيانة فقط: المقام صفوف الصيانة ذات التاريخ المخطط حتى اليوم، والبسط الزيارات المكتملة في أو قبل تاريخها المخطط. أشرطة الالتزام جيدة عند 70% فأعلى، تحذيرية من 40% إلى أقل من 70%، ومنخفضة تحت 40%.
- يستعمل استيراد Excel معالجاً موحداً داخل المتصفح باستخدام SheetJS الموجود أصلاً، للملفات `.xlsx` حتى 5 MB. لا تحدث كتابة قبل معاينة المستخدم وتأكيده؛ تُجزأ الكتابات الكبيرة. تُحصر عمليات الاستيراد في `admin` و`project_manager` و`area_engineer` بسياسات RLS، وتُحفظ اختلافات أسماء المشرفين والمهندسين اختيارياً في `supervisor_aliases`.
- تعرض معاينة التسكين أرقام الإقامة مقنعة فقط. لا يقرأ العميل أعمدة `residence_no`؛ مطابقة/إنشاء عامل النظافة وتحديث تسكينه تتم ذرياً عبر `resolve_import_cleaner` المفحوصة بالدور، وإضافة رقم إقامة البواب تكتب إلى العمود المحمي دون إرجاعه.
- تُحدّث إعادة استيراد الخطة الشهرية السجلات بمفتاح `(plan_id, school_id)` ولا ترسل حقول الزيارة أو التقرير، كي لا تمسح الإنجاز المسجل. يبقى عمود `responses_count` التاريخي دون استخدام في التطبيق أو الاستيراد.
- يكون التقرير متأخراً فقط بعد انقضاء شهر الخطة مع بقاء التقرير غير مكتمل؛ لا توجد مهلة سماح قابلة للضبط ولا موعد يومي لتسليم التقرير.
- تقرير الخطط الشهرية يحسب الزيارة والتقرير المكتملين من أعمدة الحالة/التاريخ في `monthly_plan_rows`، ويستعمل عدد صفوف الخطة مقاماً للنسب؛ المتوقع حتى التاريخ هو الصفوف التي تاريخها المخطط لا يتجاوز تاريخ «كما في». اكتمال الصف يتطلب زيارة وتقريراً، والمتبقي هو غير المكتمل، وقيد الإجراء هو زيارة مكتملة مع تقرير غير مكتمل. تستخدم المقارنة الشهر السابق اليوم المناظر مع قص اليوم إلى آخر يوم متاح في ذلك الشهر.
- لا تعد الزيارة متأخرة إلا بعد تاريخها المخطط؛ لا يعد التقرير متأخراً إلا بعد آخر يوم في شهر الخطة. التقارير المعلقة أثناء الشهر مستحقة بنهايته، ويظهر خطرها مرتفعاً عندما يتجاوز عددها أيام العمل الباقية. أيام العمل في التقرير من الأحد إلى الخميس؛ التوقع إلى نهاية الشهر تقدير خطي من الزيارات الفعلية حتى التاريخ مقسوماً على أيام العمل المنقضية، ومحدود بعدد الزيارات المخططة.
- درجة التزام المشرف في التقرير العام = 50% اكتمال (زيارة وتقرير) + 25% نسبة الزيارات + 25% نسبة التقارير؛ ترتيب الأكثر تأخراً بحسب حالات الزيارة والتقرير المتأخرة. لا تدخل خطتا المصاعد والأمن والسلامة في ترتيب المشرفين، ويعرض اسم المقاول الخارجي بدلاً منه. يعد تاريخ زيارة سابقاً للمخطط بسبعة أيام أو أكثر شذوذاً لجودة البيانات.
- تكرار رؤوس الاتصال وإعدادات التبويب/الإحداثيات تجعل الربط إعداداً صريحاً، لا تخميناً.
- `docs/reference/001_shalfa_schema_rls.sql` هو مرجع المخطط والسياسات المطبق في Supabase. لا يُعاد إنشاؤه أو استبداله؛ أي حاجة تطبيقية تضاف فوقه بترحيل تراكمي.
- ترحيلات `202611030001`–`202611030004` بُنيت على مخطط أولي مختلف، وهي متجاوزة ولا تُشغّل بجانب المخطط 001. تُطبق الترحيلات التراكمية من `202611040001` فصاعداً بالترتيب الموثق في `docs/SCHEMA_RECONCILIATION.md`؛ لا تعدّل ترحيلاً منشوراً.
- قراءة أرقام الإقامة محظورة عبر صلاحيات الأعمدة؛ تعرض فقط عبر `reveal_residence` المدققة. تقييمات الموظفين وبيانات KPI محصورة بمدير النظام ومدير المشروع.
- لا يمكن اعتبار نموذج KPI مطابقاً للملف أو إطلاقه قبل توفير المصنفين والتحقق من صيغ الخلايا.
- المخرجات التعاقدية الـ28 تُستورد من تبويب `المخرجات (28)` بعملية seed متكررة آمنة؛ تحدث بيانات التعريف دون إرسال الحالة أو تواريخ التسليم/الاعتماد أو الموعد اليدوي أو الملاحظات. تحسب المواعيد العددية بإضافة الأيام التقويمية إلى تاريخ الأساس المقابل في `app_settings`؛ لا يخمن التطبيق أساساً أو تاريخاً غير متوفر، وتبقى أسس نهاية العقد/حسب الخطة والمدد النصية بحاجة إلى موعد يدوي. المتأخر هو ما تجاوز موعده المحسوب أو اليدوي وحالته `not_delivered` فقط؛ المسلّم بانتظار الاعتماد والمعتمد ليسا متأخرين. تعديل المخرجات محصور بمدير النظام ومدير المشروع، والمهندس المناطقي للقراءة فقط. يدعم الدليل المرفق bucket الخاص `evidence` وحد 10 MB وأنواع MIME المحددة في المخطط.
